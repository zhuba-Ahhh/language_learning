# LinguaDesk 功能重构设计

日期：2026-10-07。状态：首批训练工作台已实施，实际范围与验证见[重构实施记录](./rebuild-verification.md)。本文保留最初审查与后续目标。

本文替代旧版功能规划中的产品入口、首批用户和实施顺序；旧文档保留为历史参考。

## 1. 为谁解决什么问题

用户是计算机专业学生，英语能读懂简单内容、口语一般，日语零基础。长期希望到日本工作和生活，同时准备雅思与日语等级考试。

产品定位：围绕真实任务练习英语和日语的个人训练软件，以口语和阅读为主。每次学习都应得到一份可回看的结果，以及明确的下一次练习。

已确认的边界：纯前端；英语与日语；口语、阅读优先；正文、题目与解析在 Web 项目内；所有页面在应用内完成，不跳转外部网站；音频等资源允许 CDN 或内置；界面浅色、短文案。

本方案的可调整默认值：

- 英语目标暂按 IELTS 6.5 组织路线，不据当前描述推断考试分数或 CEFR 等级。
- 日语先从入门到 N5/N4，再向 N3/N2 发展；阶段推进依据训练结果，用户也可自行选课。
- 每日时间暂设 30 分钟，可改为 15/30/45 分钟；两种语言共享这份预算。
- “PC”暂解释为桌面浏览器与可安装 PWA，和移动 Web 使用同一套前端；原生安装包另有打包工作。
- 雅思阅读首批暂采用 Academic 方向，目标设置保留类型信息，不能混用 A/G 阅读材料。

### 2.1 功能错位，优先于外观调整

| 问题                       | 当前证据                                                                                                            | 重构要求                                               |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 日语任务进入英语材料       | `courses.json` 中 16 个日语任务指向 `en-tech-easy`；例如 `day-16-task-1` 文案是「〜は〜です」，实际指向英文函数短文 | 内容引用必须存在、语言一致、训练方式匹配               |

| 英语与日语不能同时形成路线 | `goalId` 只选一个目标；自由口语与阅读也没有按当前语言筛选                                                           | 使用全局语言上下文，每种语言独立保留阶段与目标         |
| 课程随日期自行推进         | Provider 根据开始日期与今天的差值选择数组项，结束后停留在最后一项                                                   | 按学习单元完成情况推进，漏学不会导致跳课               |
| 口语完成条件过于宽松       | 停止任意一句录音即回调完成课程任务，未检查要求的轮次或时长                                                          | 明确每类练习的提交条件，录音结束与任务完成分开         |
| 练习结果没有可用反馈       | 阅读只存总正确数；假名只在第十题记录一次；没有逐题作答与错因                                                        | 保存实际作答、提示使用、错题和下一步动作               |
| 进度忽略自由训练与重练     | 进度使用 `sessions`，同一课程任务只记录一次；不使用 `attempts`                                                      | 按实际尝试统计，课程完成与练习次数分开展示             |
| 零基础缺少学习支架         | 日语正文没有逐句译文、正文振假名和句型拆解；现有自我介绍直接涉及专业敬语                                            | 提供读音、分句、简单句型与替换练习，按需展开           |
| 复习仅等于不熟单词         | ReviewSection 只读取 `unknown`；总数随标记变化                                                                      | 生词、错题和待重录句子进入有日期的复习队列             |
| 文档与代码不同步           | 旧规划仍描述无录音、无站内文章、148 词；README 仍描述已修复的 lint 阻断                                             | 当前能力以本轮审查为准，明确历史规划与已实施功能       |

以上包括代码审查发现与页面观察；本轮没有录音、提交答案、切换学习目标、导入或清空用户数据。当前 lint 与生产构建通过，检查到的浏览器控制台无 error/warn。浏览器证据采集脚本无法连接内置浏览器的 CDP 页面目标，页面状态通过浏览器接口直接检查；未产出自动化 HTML 验收报告。

## 3. 两条学习路线，贯穿生活与专业背景

考试是训练方向之一，同一语言中的考试、生活和 IT 内容可以并行练习。用户不必通过“更换目标”才能切换到另一类材料。

| 路线 | 起步内容                                                  | 后续进阶                                                   | 具体能力目标示例                                   |
| ---- | --------------------------------------------------------- | ---------------------------------------------------------- | -------------------------------------------------- |
| 英语 | 简单分级短文、基础句型、个人与校园话题、30—60 秒表达      | 雅思 Part 1 → Part 2/3、阅读题型；技术文档、项目与面试表达 | 读懂一篇新短文并复述；回答追问；介绍自己做过的项目 |
| 日语 | 假名与发音、极短对话、です/ます、时间与位置、带读音的短句 | N5/N4 读解 → N3/N2 读解；生活办事、职场确认与 IT 沟通      | 读懂车站通知；完成预约对话；解释工作进度和请求帮助 |

日语零基础先学清音、基础发音和短句，再逐步引入浊音/拗音及简单短文。专业词汇作为熟悉场景里的补充，不作为入门的主要难度来源。

英语材料覆盖校园、生活、教育、科技与环境。IT 阅读是特色内容，但雅思阅读不能全部用编程文章替代。

JLPT 不直接考口语和写作，因此日语“读解备考”和“生活/工作口语”分别保留训练结果；不能把通过等级等同于能顺利交流。[JLPT 官方说明](https://www.jlpt.jp/e/about/points.html)

## 4. 新入口与页面职责

主导航改为「今日 / 口语 / 阅读 / 复习 / 记录」。英语/日语切换固定可见；路线与目标配置放在语言摘要或记录页的设置中。词库、闪卡、假名、句型在相关训练中使用，不再和两项核心能力争夺入口。

| 页面 | 首屏只回答的问题             | 核心内容与操作                                                            |
| ---- | ---------------------------- | ------------------------------------------------------------------------- |
| 今日 | 我现在该练什么？             | 继续上次、一个主训练、短复习；显示实际预算，点击直接到对应材料            |
| 口语 | 我能不能说出来？             | 按阶段与场景选题；听、跟读、复述/回答、录音、回听、自评、重录             |
| 阅读 | 我能不能读懂？               | 分级材料；正文、按需提示、题目、原文依据、结果；读后进入复述              |
| 复习 | 哪些内容需要再练？           | 到期生词、错题、待重录表达；小批次训练与明确结束状态                      |
| 记录 | 我有哪些进步，下一步是什么？ | 分语言结果、阅读正确率/用时、录音历史、单元完成度；目标、预算、备份与设置 |

页面文案以「继续」「听」「录音」「回听」「重练」「加入复习」等具体动作命名。资料解释默认收起；阅读原文的长度按学习需要保留，不能为了“字少”删掉训练材料。

桌面：固定语言切换与紧凑导航；阅读采用正文/题目双栏，口语采用题目/录音反馈双栏。训练区优先给内容，不用大幅装饰占据操作空间。

移动：同一套内容与进度；单栏正文，题目/提示用面板切换，录音与提交按钮靠近底部。目标设置不重复成为一张独立的空白导航页。

## 5. 口语训练从“录一句”变成完整动作流

共同流程：看任务 → 听示范 → 带提示练习 → 隐藏示范回答 → 保存录音 → 回听并自评 → 选择重录或安排复习。

| 训练方式 | 材料必须提供                        | 完成后留下什么                     |
| -------- | ----------------------------------- | ---------------------------------- |
| 跟读     | 示范句、译文、可展开的发音提示      | 关联到本句的录音、自评、练习次数   |
| 替换表达 | 基础句型、可替换槽位、具体情境      | 用户自己的回答录音，而非只重复示范 |
| 读后复述 | 关联文章、要点、复述问题            | 关联文章的回答与再次复述记录       |
| 情境应答 | 角色、任务、固定追问、参考表达      | 一次完整场景的回答；允许隐藏参考   |
| 雅思专项 | 实际问题或题卡、Part、准备/作答计时 | 同题历史录音、完成情况、自评维度   |

情境应答首批采用内容中预先编写的轮次，纯前端即可运行。雅思必须有题目和题卡，参考答案不能代替题目。

IELTS Part 2 的考试式训练采用 1 分钟准备、最长 2 分钟作答；初学者可以另用较短的练习模式，记录时区分两者。当前草稿“组织一分钟回答”只可视为训练提示。[IELTS Speaking 官方说明](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-speaking)

纯前端首批提供录音、时长、轮次、用户自评和历史比较。可靠的自动发音评分与雅思估分尚无实现依据，不展示自动考试分数。语音识别可后续作为可选转写能力，不能成为录音练习的必需条件。

## 6. 阅读训练从“答两题”变成读懂与使用

共同流程：选择适合当前阶段的材料 → 阅读 → 按需查看读音/译文/句型 → 作答 → 查看原文依据和错因 → 收集生词 → 用口语复述。

- 英语：先训练主旨、细节、长句结构和复述，再增加雅思判断、标题匹配、填空等题型。
- 日语：先支持人工整理的正文振假名与译文，再训练通知、行动顺序、信息检索；句型解释紧贴正文。
- 生词保存上下文和来源材料，复习时能回到原句；可以收集短语，不只保存孤立单词。
- 入门问题可以使用中文，考试式训练按目标使用原语言；提示使用与计时模式分别记录。
- 客观题依据内容答案判分，每题提供原文段落或句子定位。首批不依赖在线模型临时生成解析。

IELTS Academic 完整阅读是 60 分钟、3 个部分、40 题；首批短文和单题型训练明确标为专项练习，不包装成完整模考。[IELTS Reading 官方说明](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-reading)

## 7. 内容如何补充，代码如何复用

先使用三个稳定概念，延续现有 React、TypeScript 与 Less：

| 概念     | 最少需要保存的内容                                                           | 现有代码的演进                                                     |
| -------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 学习配置 | 当前语言；两种语言各自的起点、方向、目标；共享每日预算                       | 从单一 `goalId` 演进；考试与生活方向不互斥                         |
| 学习单元 | 稳定 ID、语言、阶段、主题、正文/对话、阅读题、口语任务、关联词汇、来源与版本 | 在 `content` 中组织；逐步替代文案与实际动作不一致的 `courses.json` |
| 实际练习 | 内容与版本、语言、训练方式、时间、作答明细、结果、自评、录音引用             | 扩展已有 `StudyAttempt`；进度与复习读取它                          |

阅读器与口语训练器复用交互；考试通过明确的题型和计时配置表达。词汇、句型与假名只是可复用内容类型，不建设通用插件系统或第三种语言框架。

新增材料的流程：选择语言/阶段/主题 → 编写完整单元 → 校对答案与提示 → 校验引用和语言 → 补齐 CDN 配音 → 加入对应路线。优先按完整单元补充，而不是批量加入只有释义的词条。

构建前校验必须覆盖：ID 唯一、材料引用存在、任务语言一致、必需题目/示范齐全、答案与解析合法。未通过校验的单元不进入今日推荐。考试等级是内容整理标签，应记录依据，不能把第三方词表当官方完整范围。

专业主题优先整理：校园与课程、项目介绍、README/API 文档、Bug 描述、PR/Code Review、站会、面试。生活主题优先整理：自我介绍、问路/交通、购物/点餐、预约、租房、日常确认。

## 8. 纯前端存储、音频与 PC 形态

- localStorage 保留轻量偏好；实际作答、复习状态和录音 Blob 用 IndexedDB 保存，录音不序列化成 JSON 字符串。
- 示范音频继续使用现有配音的 CDN 地址。新增文本在内容准备阶段生成，避免首次正式学习才等待远程生成。
- 自定义词条的在线 TTS 可保留为补充。未联网或播放失败时明确提示，不影响正文阅读和本地录音回听。
- PWA 提供桌面安装入口与应用壳离线使用；正文与个人记录本地可用。未缓存的 CDN 示范音频仍需要网络，不能宣称首次安装即完全离线。
- 不自动跨设备同步；提供手动备份/恢复。含录音的完整备份与轻量 JSON 记录备份分别标明范围。
- 旧 v1/v2 数据保留导入能力，材料 ID 不重用；旧打勾只能迁移为历史完成，不能制造考试成绩或补出从未记录的答案。
- 迁移后可查询旧记录并确认一致性，再考虑清理旧存储。重置要明确“当前语言”或“全部数据”，覆盖录音、复习与假名记录。

### 9.1 第一批英语样例

单元「介绍我的专业」：

1. 首页显示英语起步路线、所需时间和「继续」。
2. 阅读一篇贴近当前水平的计算机学生自我介绍，按需查看句意。
3. 回答主旨与细节题，看到原文依据；选择加入一个短语到复习。
4. 用“专业 → 兴趣 → 正在做的项目”的提示回答，录制 30—60 秒。
5. 保存并回听，选择「还需提示 / 能独立表达」，安排下次重练。
6. 刷新后仍能恢复结果与录音；记录显示本次练习而不是只有课程打勾。

第二个单元「我的一天」检验新内容是否能复用同一流程，防止把第一课写死。

### 9.2 第一批日语样例

单元「はじめまして」：

1. 首页显示日语入门路线，可先练与本课有关的假名。
2. 读带振假名和按需中文译文的极短介绍；展开「〜は〜です」解释。
3. 回答简单理解题，跟读「学生です」等短句。
4. 用自己姓名与专业替换示范信息，隐藏示范后录音。
5. 保存、回听、自评、加入复习；刷新后能恢复。
6. 切换英语再切回日语，回到各自的学习位置，不改变另一语言的数据。

第二个单元「これは何ですか」检验句型、读音与生活场景的复用。
